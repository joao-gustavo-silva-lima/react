# DevLinks Dashboard

DevLinks Dashboard is a React + TypeScript single-page application for managing and browsing personal links. It communicates with the DevLinks Express API, renders link cards and summary metrics, and supports creating, updating, deleting, filtering, and tracking link access.

## Requirements

- Node.js and npm
- A running instance of the DevLinks Express API on the default backend port (`http://localhost:3000`)

## Getting started

Clone the repository and move into the project directory:

```bash
git clone https://github.com/joao-gustavo-silva-lima/react.git
cd react/devlinks-dashboard
```

Install dependencies:

```bash
npm install
```

Create a `.env` file in the project root and configure the API base URL:

```env
VITE_API_BASE_URL="http://localhost:3000/api/v1/links"
```

Start the development server:

```bash
npm run dev
```

The application is served by Vite and usually becomes available at `http://localhost:5173`.

The application follows a layered client-side composition model:

- `App.tsx` composes the dashboard shell and passes shared state between the query hook and UI components.
- `useLinksQuery.hook.ts` fetches the initial list from the API and exposes a refetch helper.
- `LinksAPI` centralizes all fetch calls, including list, create, update, delete, and redirect operations.
- `Modal.tsx` and `useFormValidation.hook.ts` validate input before submission with Zod-based rules.
- `LinkList.tsx` renders the cards, applies local filtering, and manages user actions such as delete and redirect.

## Features

The dashboard provides the following user-facing behavior:

- List all links returned by the API in a responsive card layout
- Display aggregate metrics such as total links, total clicks, and the most common category
- Search links by title and filter by category
- Register new links through a modal form
- Update existing links without reloading the page
- Delete links with confirmation
- Open a destination URL in a new tab and increment the click counter through the API redirect endpoint

## Data model and storage

The client uses the following link data contract, matching the backend response generated by the API:

| Field | Type | Description |
| ----- | ---- | ----------- |
| `id` | `string` | Unique identifier for the link. |
| `title` | `string` | Human-readable link title. |
| `url` | `string` | Destination URL; must be valid and use `http://` or `https://`. |
| `category` | `string` | Link category selected from the predefined values. |
| `tags` | `string[]` | Optional list of metadata tags. |
| `clicks` | `number` | Number of times the link has been accessed through the redirect endpoint. |
| `createdAt` | `string` or `Date` | Creation timestamp returned by the backend. |

The supported categories are defined as:

- `desenvolvimento`
- `design`
- `documentação`
- `ferramentas`
- `carreira`
- `estudo`
- `pessoal`

The app does not persist data locally in browser storage. All list, create, update, and deletion operations are delegated to the API. The backend is responsible for actual persistence, while the dashboard behaves as a presentation and interaction layer over that service.

## API integration

The frontend reads the API base URL from the environment variable `VITE_API_BASE_URL` and calls the following endpoint family:

Base URL: `http://localhost:3000/api/v1/links`

| Method | Path | Description |
| ------ | ---- | ----------- |
| `GET` | `/` | Fetches the full list of links or applies query filters. |
| `POST` | `/` | Creates a new link entry. |
| `GET` | `/:id` | Fetches one link by its id. |
| `PUT` | `/:id` | Updates an existing link. |
| `DELETE` | `/:id` | Removes a link. |
| `GET` | `/:id/redirect` | Returns the redirect URL and increments the click count. |

The client serializes form data into the API contract through `formDataToLinkPrototype()` and validates request payloads with Zod before transmission. The request layer is centralized in `src/api/links.api.ts`.

## Validation and UX rules

The dashboard includes client-side validation for the modal form:

- Title is required and must have at least 3 visible characters
- URL must be a valid `http` or `https` URL
- Category must match one of the allowed values
- Tags must be formatted as comma-separated values and limited to 5 entries
- Input errors are shown inline in the modal while preserving a responsive user experience
